## Choice 1 — 新增表结构和数据

**功能**：创建一个新表（含字段定义），建表后询问是否插入数据；若表已存在则直接进入数据插入模式，支持循环插入多条记录。

**操作流程（新建表）**：

```
> 1
please enter your new table name: students
please input the number of feilds in table students: 4
please input the name of field 0 : s_id
please input the type of field(0-> str; 1-> varstr; 2-> int; 3-> boolean) 0 : 0
please input the length of field 0 : 10
please input the name of field 1 : name
please input the type of field(0-> str; 1-> varstr; 2-> int; 3-> boolean) 1 : 0
please input the length of field 1 : 10
please input the name of field 2 : gender
please input the type of field(0-> str; 1-> varstr; 2-> int; 3-> boolean) 2 : 0
please input the length of field 2 : 10
please input the name of field 3 : age
please input the type of field(0-> str; 1-> varstr; 2-> int; 3-> boolean) 3 : 2
please input the length of field 3 : 4
Table created. Insert data now? (y/n): y
Input field name is: s_id  field type is: 0 field maximum length is: 10 (. to stop)
s01
...
.
OK!
```

输入 `n` 则跳过插入直接返回菜单。

**表已存在时**，直接进入循环插入：
```
> 1
please enter your new table name: students
Input field name is: s_id  field type is: 0 field maximum length is: 10 (. to stop)
s01
Input field name is: name  field type is: 0 field maximum length is: 10
Tom
...
Input field name is: s_id  field type is: 0 field maximum length is: 10 (. to stop)
.
OK!
```

**字段类型说明**：`0`=定长字符串，`1`=变长字符串，`2`=整数，`3`=布尔

## Choice 13 — 带事务持久性的插入

**功能**：使用 WAL（Write-Ahead Logging）机制插入记录，保证事务持久性。系统崩溃后可通过 Choice 14 恢复。

**操作流程**：与 Choice 1 的插入相似，但每次插入会自动：
1. 开启事务（`BEGIN` 日志）
2. 记录后像到 WAL
3. 写入 `.dat` 数据文件
4. 提交事务（`COMMIT` 日志 + fsync）

```
> 13
please enter the table name: students
Input field name is: s_id  field type is: 0 field maximum length is: 10
s04
Input field name is: name  field type is: 0 field maximum length is: 10
Mike
Input field name is: gender  field type is: 0 field maximum length is: 10
male
Input field name is: age  field type is: 2 field maximum length is: 4
21
Insert with transaction succeeded!
```

## Choice 14 — 崩溃恢复（重放 WAL 日志）

**功能**：读取 `wal.log`，执行崩溃恢复：
- **REDO**：重做已提交但可能未持久化的事务（后像写入 `.dat`）
- **UNDO**：回滚未提交的事务（前像恢复到 `.dat`）

```
> 14
#        Crash Recovery (Replay WAL Log)          #
Recovery actions:
  Transaction 1: REDO INSERT into students
  Transaction 2: UNDO INSERT from students
  Transaction 3: UNDO UPDATE on students
#----------------------------------------------------#
```

**恢复规则**：
- 有 COMMIT 日志的事务 → REDO（保证持久）
- 无 COMMIT 日志的事务 → UNDO（回滚到前像）

## Choice 15 — 查看 WAL 日志

**功能**：以可读格式显示 `wal.log` 中的所有日志记录。

```
> 15
#        WAL Log Contents                          #
  [BEGIN] txn=1 table= before= after= ts=2026-06-13 14:30:00
  [INSERT] txn=1 table=students before= after=s04|Mike|male|21 ts=2026-06-13 14:30:00
  [COMMIT] txn=1 table= before= after= ts=2026-06-13 14:30:01
  [BEGIN] txn=2 table= before= after= ts=2026-06-13 14:35:00
  [INSERT] txn=2 table=students before= after=s05|Ghost|male|99 ts=2026-06-13 14:35:00
#----------------------------------------------------#
```

**日志类型说明**：

| 类型 | 含义 |
|------|------|
| BEGIN | 事务开始（分配事务 ID） |
| INSERT | 插入操作（前像为空，后像为新记录） |
| UPDATE | 更新操作（前像为旧值，后像为新值） |
| COMMIT | 事务提交（数据已持久化） |
| ABORT | 事务回滚 |

## 数据文件说明

| 文件 | 格式 | 说明 |
|------|------|------|
| `all.sch` | 二进制 | 所有表的模式定义（MetaHead + TableNameHead + Body） |
| `<表名>.dat` | 二进制 | 每表一个数据文件（Block_0 元数据 + Block_i 数据块） |
| `<表名>.ind` | 二进制 | B 树索引文件 |
| `wal.log` | 二进制 | WAL 日志文件（每条记录 560 字节） |
